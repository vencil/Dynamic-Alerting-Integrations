# CI / test Python dependency constraints — SSOT (#1158 root-solve).
#
# HOW THIS IS USED
#   Every `pip install <pkgs>` step in .github/workflows/** and the
#   devcontainer references this file with `-c requirements/ci-constraints.txt`.
#   As a pip *constraints* file it does NOT install anything on its own —
#   it only pins the version of a package IF that package is being
#   installed. So each job keeps its own readable, explicit dependency
#   list; only the versions are centralized here.
#
# WHY PINNED
#   `pip install <pkg>` with no version tracks *latest* on every CI run.
#   For behavior-affecting tools (test runner / generator / coverage /
#   schema validation) a new release can silently drift test outcomes,
#   rename a health check, or flip a coverage gate — the "local green,
#   CI first-run red" version-drift class (#1158, originally surfaced by
#   the schemathesis `filter_too_much` seed-flake). Freezing every CI
#   Python dep here makes runs reproducible and turns each upgrade into
#   an explicit, reviewable PR.
#
#   ⛔ Renovate does NOT open those PRs, and does not watch this file.
#   `renovate.json` is deliberately images-only (`enabledManagers:
#   ["custom.regex"]`, #902 L3) and none of its customManagers match
#   `requirements/**` — so no bot ever bumps a line here. Python / Go /
#   npm lang-deps are Category C in docs/internal/dx-tooling-backlog.md,
#   deferred until the CI matrix is stable; until that trigger fires,
#   tests/ops/test_renovate_config.py pins the images-only scope.
#
# UPGRADE
#   Do NOT hand-edit to chase latest. Every bump here is hand-authored:
#   change the line deliberately in its own PR and re-verify, since the
#   new version lands in every CI lane that installs the package. A new
#   unpinned `pip install` is blocked by the `check_unpinned_deps` gate
#   (scripts/tools/lint/).
#
#   Transitive deps are pinned too: `check_unpinned_deps` only sees the
#   packages a `pip install` NAMES, so a dependency of a pinned package
#   used to float (#3538: pytest-cov's `coverage` moved 7.17.0 -> 7.17.1
#   and turned a CI shard red). The guard
#   tests/shared/test_ci_constraints_transitive_pins.py walks the installed
#   metadata and fails on any reachable distribution with no pin here.
#   When you bump a direct dep, re-pin what it now pulls in along with it.
#
# Versions below = the latest at pin time = what unpinned installs were
# already pulling, so pinning is behavior-preserving.
